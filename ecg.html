Classifying heartbeats into five types with a residual 1D CNN

A deep learning model that sorts single ECG heartbeats into five classes, trained on about 109,000 beats from the MIT-BIH Arrhythmia Database. The hard part is that 83% of beats are normal and the rarest class is under 1%.

The problem

Reading ECG recordings by hand is slow, and doctors do not always agree. A model that flags abnormal beats reliably would help. The dataset has 87,554 training beats and 21,892 test beats. About 83% are normal, and the smallest class has only 641 training examples.

With data this uneven, accuracy is misleading. A model that says "normal" every time is 83% accurate and useless. So I judged the model on macro-F1, which gives every class equal weight.

The model

I chose a 1D convolutional network because what separates beat types is the local shape of the waveform. Convolution filters slide along time and learn those shapes. The final model adds residual connections, which let a deeper network train stably.

  • Three residual blocks with 32, 64 and 128 filters, then global average pooling and a dense layer.
  • Batch normalisation and dropout to control overfitting.
  • Hyperparameters chosen by random search over 12 configurations, each scored with stratified 5-fold cross-validation.

Testing my own assumptions

I ran a two-by-two experiment: plain or residual architecture, with or without class weighting. Class weighting is the standard fix for uneven data, so I expected it to help.

Class weighting made things worse in both architectures. The rare classes still had enough examples to learn from, and the weights pushed the model to over-predict them. Residual connections helped in every case, most of all on the two hardest classes.

Where it still fails

Two classes stay hard, with recall below 0.84. A t-SNE plot of the model's internal features shows why: those beats sit inside the cloud of normal beats instead of forming their own clusters.

Other limits I report: the test split does not separate patients, so the same patient can appear in training and test. And the model sees one beat at a time, with no rhythm context.

Numbers on this page come from the public repository. The run in my submitted report scored slightly higher (98.95% and 0.937), because GPU training is not fully deterministic.
